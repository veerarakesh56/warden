ECS lines run LOG, APPSG, TASKROLE, deployment STATE, events STATE, stopped STATE/EVENT, network CHANGE. k8s lines run EVENT, STATUS, previous, ROLLOUT, current, then APPSG and nodegroup STATE.

Labels match `labels_for` for every namespace used. Siblings appear only for `AWS/*` namespaces, and `alarm_value` is used for ContainerInsights.

Examples: `ecs logs: logs: /ecs/...`, `lambda/<fn> logs: logs: ...`, `k8s/<dep>: <pod>/<ctr>: [rejected as a bad request] (400) ...`, `[failed (unclassified)]` for a `LookupError` or plain `ToolError`, and an alarm reader that stops before CloudTrail when `ListMetrics` fails.

**ECS details.** The ECS deploy dicts and config-only `changed=` match the readers. ECS on EC2 bridge mode correctly has no APPSG line. Every `task_stop_cause` classification checks out.

**Lambda details.** The CODE and SOURCE excerpt in code-decoy matches `parse_tracebacks`. The esm-disabled case correctly omits every absent series.

**Answer key.** Every other key was checked. These are right: no_fault keys, incomplete keys, multi-fault keys including escalate, `escalate_to_human` for the ENI, clock-skew, HPA, IP-exhaustion and `:latest` cases, and every target.
