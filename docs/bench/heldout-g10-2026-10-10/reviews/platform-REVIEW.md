# G10 platform held-out set: independent review

Reviewed 2026-10-10 by an independent reviewer agent (Claude). I read all 44 incidents, key.json and the README line by line,
and checked the formats against `C:\work\warden-g1\src\warden\` `aws_stack.py`, `aws_backend.py`, `aws_describe.py`,
`resources.py`, `tools.py`, `evidence.py` and `models.py`. I did not read verifier/grounding/graph/catalog/resolver/platforms/data/tests/docs/scripts.
No files were changed except this one, and no AWS calls were made.

## Mechanical checks (all pass unless a row below says otherwise)

- Kinds are 26 fault, 6 multi_fault, 6 no_fault and 6 incomplete. 23 cases are novel, 16 of them single faults. Both match the README.
- Alert labels equal `resources.labels_for(namespace, dims of the ALARM line)` + `alarm` in 42 cases. The exceptions are plat-38 (see its row) and plat-37 (no ALARM line).
- No key slug appears in any incident file. Alert names and summaries read like real alarm text, with no answer leaks.
- These lines match what the reader emits, field for field and in order: ALARM (custom namespace -> `alarm_value`, AWS namespace -> `alarm_<metric>` + `alarm_sibling_<ns>_<metric>`, metric-math), CHANGE (CloudTrail and the network form), CONFIG appconfig (before ALARM), CONFIG lambda (env allow-list correct, e.g. `APPCONFIG_APPLICATION` name-only), STATE (`aws_describe.state_line` incl. `Configuration_EngineVersion_EffectiveEngineVersion`, `JobRuns=10(...)`, `Events=1`, `InUseBy=0`), ECS STATE/EVENT (400-char cut, `task_stop_cause` classes), APPSG/TASKROLE, ESM, RULE, and the TOOL-PARTIAL chains in tool_errors.
